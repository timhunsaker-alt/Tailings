That covers Tailings' ventilation, headframe hopper, paste wall breach, paste catch-up and the all-HMC dry mill; and Wildcatter's ash bed, spin-up, the six reactor rules, the dome grid and the mud gel. Three are off even in new worlds:

    - `cascadeSpinUp`;
    - `paste_wall_breach`.

    Everything else defaults on in new worlds, including `reactorRealHeatup` (the reactor heats up in real hours).

    **Built for Tailings** (branch `answers`): `OptInRules`, saved with the world (`data/tailings/rules.dat`): `ventilation_interlock`,
    `stale_air`, `headframe_hopper`, `paste_unloaded_cure`, `dry_mill_all_hmc` on in a new world, `paste_wall_breach` off. A world is
    new when its rules are first made at server start with its game time still 0 and no Tailings data saved in it; otherwise every rule
    is off. A rule a world never saved is off. `/tailings rule` lists them, `/tailings rule <name> <true|false>` sets one (operators).
    The old `config/tailings-rules.properties` and `config/tailings-ventilation.properties` are read once, when a world's rules are
    made: a key either sets explicitly wins over that world's default. Scenes `rules_new_world`, `rules_existing_world`,
    `rules_command`. Decisions logged in "Decisions made building these" below.

## Decisions made building these (2026-11-10)

- **New or existing, how it is told:** at server start, a world with no `data/tailings/rules.dat` is new only if its game time is 0
  and no `data/tailings` folder exists in it or any dimension. Every world played for a tick before this version has a game time over
  0, so it loads with every rule off. A world made with these rules keeps them; a rule added in a later version is off in it until set.
- **The old files:** read once, as a seed: a server that turned a rule on in `tailings-rules.properties` or `interlock=true` in
  `tailings-ventilation.properties` keeps it on when an existing world first loads, and `=false` turns one off in a new world. After
  that, the world's rules and the command decide; the files are not read again.
- **Rule names:** `ventilation_interlock` and `stale_air` (the old ventilation file's `interlock` and `stale_air`); the gaps2 names kept.
- **Paste pace:** the 10x is in the fill, not the plant: a placed block stands for 10 m³ of paste. A faster pump alone could not do it,
  as all of a plant's tails make only about 34 m³ of paste an hour. Cement per block of void falls 10x with it.
- **All HMC to the dry mill:** only for a filter with a dryer touching it. Without a dryer the filter pays the spirals' 50 % as before,
  so a plant without a dry mill keeps its 2x rung (a plant stopping at any rung pays that rung). A heap of HMC carries what it pays
  (`HeavyMinerals.pay`): the spiral bank's share 1.0 a kg, the scavengers' 1.11; a bag carries its rate to a thousandth.
- **XRT reverse by the same click:** the screen's ten settings are the five steps, then the five in reverse. The useful light-ore
  setting is LOW in reverse (graphite and borax under 11.5; country rock over it).
- **The mixer's gauges:** LEVEL and DENSITY both read the paste hopper (2 t), so the two readings are of one tank.
- **Raw ore:** an ore's mined drop from Wildcatter (`wildcatter:galena`, `wildcatter:heavy_mineral` and the rest: what Fortune
  multiplies) is a raw ore item too, so it is refused with raw iron, copper and gold.
- **Game tests:** the test server makes a new world, so scenes run with the rules on. Scenes of an older world run in a batch of
  their own with every rule off (`existing_world`); scenes that turn a rule off and on run in another (`rule_scenes`), so no scene sees a
  rule change under it.

## Wildcatter needs

For #9's chlorinator compat. Wildcatter 0.5.1 to 0.6.0 has no way for Tailings to give the chlorinator zircon: the
`ChlorinatorBlockEntity` takes zirconium only from a `mineral_separator` (`ZrLineBlockEntity`) it touches, and that separator's hopper
takes only Wildcatter's own `heavy_mineral` item (`stack.is(OreBlocks.MINERALS.get(Ore.HEAVY_MINERAL))`), not a tag. What Wildcatter
needs:

1. An item tag `wildcatter:zircon_feed`, and a way to say a kg figure for an item in it. Proposed: the mineral separator's hopper takes
   any item in `#wildcatter:zircon_feed` as zircon (ZrSiO4) by kg, straight to the zirconium it holds for the chlorinator, skipping the
   ilmenite, rutile and monazite split (a concentrate is already separated). Its own `heavy_mineral` keeps its path.
2. The kg an item carries: a data map or a small JSON (`data/wildcatter/zircon_feed/<item>.json`, `{"zircon_kg": 56.25}`), or a
   component, so Tailings' `tailings:zircon_concentrate` counts 56.25 kg of zircon (l6-dry-mill.md #14).
3. Tailings then adds `tailings:zircon_concentrate` to `data/wildcatter/tags/item/zircon_feed.json` (with `"required": false`), and
   the kg file. Nothing in Tailings' code changes.

Alternatively the chlorinator itself could take the tag through its hopper (it takes carbon there now). Either way it is Wildcatter's
change; Tailings' side is a tag file.
